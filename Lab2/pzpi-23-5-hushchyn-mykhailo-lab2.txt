2 ЗАВДАННЯ
     
     Необхідно розробити мобільний програмний застосунок для будь-якої поширеної на сьогодні мобільної платформи. Мобільний застосунок повинен бути частиною системи і повинен взаємодіяти з нею. Звіт повинен містити опис прийнятих інженерних рішень. У ньому повинна бути показана будова мобільного застосунку та його взаємодія з іншими частинами системи.
     

       
     3 ОПИС ВИКОНАНОЇ РОБОТИ
       
     Мобільний застосунок WaterQuality Monitor є клієнтською частиною програмно-апаратного комплексу для автоматизації та моніторингу екологічного стану водойм. Його головне завдання – надати користувачам зручний інтерфейс для віддаленого моніторингу IoT-станцій, перегляду показників датчиків (рівень pH, каламутність, температура) та відображення геоданих у режимі реального часу. Функціональні можливості системи, а також розмежування прав між екологами, адміністраторами та безпосередньо IoT-обладнанням, детально проілюстровані на Діаграмі прецедентів (Use Case Diagram) (Рис. 1. Дод. Б). 
     Застосунок розроблено з використанням кросплатформного фреймворку React Native, що дозволяє генерувати нативні збірки для Android та iOS з єдиної кодової бази мовою TypeScript.
     Архітектура всього комплексу побудована за принципом клієнт-серверної взаємодії. Мобільний застосунок виступає виключно як шар представлення (Presentation Layer) і не виконує важких обчислень чи прямого доступу до бази даних. Внутрішня будова додатка (поділ на UI-компоненти, менеджер стану та сервіси взаємодії з API) та його зв'язок із сервером Node.js і базою даних PostgreSQL структурно зображені на UML Діаграмі компонентів (Component Diagram) (Рис. 2. Дод. Б).
     Для зв'язку з бекендом використовується протокол HTTP/HTTPS (REST API). Усі запити захищені за допомогою JWT-токенів, які передаються в заголовку Authorization. Послідовність взаємодії клієнта з системою — від етапу авторизації та завантаження списку станцій до відмальовки мапи та переходу до деталей конкретного об'єкта — покроково відображена на UML Діаграмі діяльності (Activity Diagram) (Рис. 3. Дод. Б).
     Для забезпечення модульності та зручності підтримки коду, проєкт має чітку ієрархію директорій. Логічний поділ вихідного коду на простори імен (модулі навігації, екрани, перевикористовувані UI-компоненти та сервіси API) показано на UML Діаграмі пакетів (Package Diagram) (Рис. 4. Дод. Б).
     Шар моделей (Types/Interfaces) Містить декларації типів даних (DTO), які відповідають структурі JSON-відповідей від бекенду.
     Назва інструменту ШІ: Google Gemini 1.5 Pro
Промпт для створення коду: "Create a TypeScript interface named 'Station' for a React Native application. Map the properties to a Node.js JSON response. Include properties for id, name, latitude, longitude, and status."
Внесок автора: Інтегровано інтерфейс у загальний модуль API та додано типізацію для роботи з react-query.

1. export interface Station {
2.   id: string;
3.   name: string;
4.   latitude: number;
5.   longitude: number;
6.   status: 'active' | 'offline' | 'maintenance';
7. }

     Шар логіки відображення та UI (Components & Hooks) Інтерфейс побудовано з використанням функціональних компонентів React та хуків. Для управління асинхронним станом (завантаження, помилки, кешування) використано бібліотеку @tanstack/react-query.
Назва інструменту ШІ: Google Gemini 1.5 Pro
Промпт: "Write a React Native screen component that fetches stations using useQuery. Display an ActivityIndicator while loading. Implement a toggle to switch between a Map view and a List view."
Внесок автора: Адаптовано стилістику компонента, додано локалізацію через useTranslation() та налаштовано навігацію useNavigation().

   Інженерне рішення: Інтеграція геоінформаційної системи (GIS) З метою оптимізації роботи додатка та уникнення залежності від пропрієтарних нативних бібліотек (Google Maps SDK), було прийнято архітектурне рішення використовувати відкриті карти OpenStreetMap через веб-рушій Leaflet.js, вбудований у нативний компонент WebView. Це гарантує стабільну роботу на будь-яких пристроях без необхідності налаштування API-ключів та вирішує проблеми з автолінкінгом нативних модулів на ОС Android.

     4 ВИСНОВКИ
       
     У ході виконання лабораторної роботи було успішно розроблено та реалізовано повноцінний мобільний застосунок для взаємодії з IoT-системою моніторингу якості води.
     Обраний стек технологій (React Native, TypeScript, React Query) дозволив створити продуктивний кросплатформений клієнт. Використання react-native-webview у комбінації з Leaflet.js виявилося надійним інженерним рішенням для відображення геоданих, що дозволило уникнути складних залежностей від нативних картографічних SDK. Завдяки модульній архітектурі, застосунок легко масштабується і може бути розширений новим функціоналом (додавання нових типів сенсорів або аналітичних графіків) без необхідності масштабного рефакторингу існуючого коду. Отриманий результат підтверджує доцільність застосування сучасних інструментів розробки для створення мобільних IoT-рішень.
