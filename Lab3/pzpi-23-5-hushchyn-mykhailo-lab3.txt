2 ЗАВДАННЯ
     
     Необхідно розробити front-end частину програмної системи. Ця частина системи повинна підтримувати роботу клієнтів у веб-режимі та забезпечувати адміністрування системи, тобто мати окремий інтерфейс для звичайних користувачів і окремий — для адміністраторів (відповідно до ролей користувачів вашої системи). Користувацький інтерфейс та інтерфейс адміністрування повинні підтримувати інтернаціоналізацію та локалізацію, а саме, забезпечувати: підтримку української на англійської мов сайту, формат дати та часу відповідний регіону, порядок сортування текстових значень, різні напрями введення тексту тощо. Адміністрування системи повинно забезпечувати: управління користувачами системи, управління даними системи, створення резервних копій налаштувань та даних, експорт та імпорт даних та налаштувань.


     3 ОПИС ВИКОНАНОЇ РОБОТИ
       
     Програмна система «Water Quality Monitor» являє собою сучасний вебзастосунок, розроблений для моніторингу та аналізу якості води на географічно розподілених станціях у режимі реального часу. Основна мета розробленої системи - надати єдиний інтерактивний інтерфейс для візуалізації телеметричних даних із різноманітних сенсорів (таких як рівень pH, температура, розчинений кисень, каламутність) та для віддаленого контролю стану обладнання (актуаторів, зокрема насосів і клапанів). Завдяки інтеграції картографічних сервісів, користувачі можуть зручно відслідковувати станції на карті та миттєво оцінювати загальний індекс якості води (WQI).
     Платформа побудована на основі гнучкої моделі управління доступом на основі ролей (RBAC), що дозволяє адаптувати робочий простір під потреби конкретного користувача, як це передбачено Діаграмою прецедентів (Див. Дод. В. рис. 1). Звичайні користувачі отримують доступ до спрощеного дашборду для перегляду публічних даних та налаштування персональних підписок на сповіщення. Водночас адміністративний і технічний персонал забезпечується розширеним інструментарієм: вони можуть аналізувати агреговану статистику за будь-який період (відповідно до логіки Діаграми діяльності) (Див. Дод. В. рис. 2), керувати конфігураціями станцій та оперативно реагувати на критичні інциденти, змінюючи життєвий цикл тривог (відкриття, обробка, закриття) згідно з Діаграмою станів (Див. Дод. В. рис. 3).
     З архітектурної точки зору, front-end частина реалізована за принципами Single Page Application (SPA), структура та взаємодія модулів якої детально відображена на Діаграмі компонентів (Див. Дод. В. рис. 4). Використання сучасних рішень для управління глобальним станом системи та оптимізації мережевих запитів через захищені маршрути гарантує високу продуктивність застосунку без зайвих перезавантажень сторінок. Крім того, впроваджена система інтернаціоналізації (i18n) та адаптивний дизайн роблять платформу максимально доступною та зручною для використання на будь-яких пристроях, незалежно від мовних або регіональних налаштувань клієнта.
     Для розробки клієнтської частини було обрано наступний стек технологій:
     - Бібліотека/Фреймворк: React.js із використанням TypeScript для забезпечення строгої типізації.
     - Стилізація: Tailwind CSS для швидкої та адаптивної стилізації. Іконки реалізовано через lucide-react.
     - Маршрутизація: react-router-dom для забезпечення навігації між сторінками.
     - Управління станом: Zustand для глобального керування станом (authStore).
     - Взаємодія з API: Axios для виконання HTTP-запитів до REST API.
     - Локалізація: react-i18next для багатомовності.
     - Мапи: react-leaflet для відображення станцій.
     Рольова модель та макети (Layouts) Архітектура передбачає чітке розділення:
     1. UserLayout: Інтерфейс для користувачів (viewers). Світлий дизайн, доступ до карти станцій, WQI, власних сповіщень.
     2. DashboardLayout: Інтерфейс для персоналу (admin, manager, analyst). Темний дизайн, керування станціями, агрегована статистика та управління системними тривогами.
     Локалізація (i18n) Система підтримує українську та англійську мови (uk.json, en.json). Усі текстові константи замінено на виклики функції t(). Приклад реалізації локалізації у компоненті AlarmsPage:

       2. 
       3. const AlarmsPage = () => {

       5.

       8.     return date.toLocaleDateString(i18n.language, { day: '2-digit', month: '2-digit' });
       9.   };
       10.

     4 ВИСНОВКИ
       
     У ході виконання лабораторної роботи було розроблено front-end частину програмної системи «Water Quality Monitor».
     Реалізовано гібридний адаптивний інтерфейс (SPA), який коректно працює як на десктопних, так і на мобільних пристроях. Успішно впроваджено рольову модель, що дозволило розділити функціонал для адміністраторів та звичайних користувачів (макети DashboardLayout та UserLayout). Інтегровано систему інтернаціоналізації (i18n), що забезпечує швидке перемикання між українською та англійською мовами та форматування дат згідно з локаллю. Взаємодія з бекендом реалізована через захищені маршрути за допомогою Axios.
     Використання штучного інтелекту значно прискорило процес написання рутинного коду (такого як створення словників перекладів, UI-хелперів та логіки оновлення глобального стану).
